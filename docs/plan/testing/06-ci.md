## 1. Раннеры

| Раннер | Железо | Что гоняет |
|---|---|---|
| `x86-cloud` | GitHub-hosted или свой x86 | Сборка, линт, уровень 0, уровень A (`smoke`, `regression`, `adversarial`) |
| `rk3588-board` | **OrangePi 5 Pro, self-hosted** | Кросс-собранный образ, уровень B `micro`, бенч рантайма |
| `gpu-rtx` | Машина с RTX 4090, self-hosted | Уровень E (Isaac Sim), тяжёлые свипы уровня A |

Плата и GPU-машина — self-hosted раннеры с ограничением конкурентности 1 (физическое железо не параллелится).

## 2. Пайплайны

### `pr` — на каждый Pull Request

| Шаг | Раннер | Время | Блокирует merge |
|---|---|---|---|
| Линт, форматирование, статический анализ | x86 | 2 мин | да |
| Сборка x86 (ROS 2, Release + Debug) | x86 | 8 мин | да |
| **Кросс-сборка aarch64** | x86 | 10 мин | да |
| Уровень 0: юнит + property | x86 | 5 мин | да |
| Уровень A: `smoke` | x86 | 1 мин | да |
| Уровень A: `regression` | x86 | 15 мин | да |
| Уровень A: `adversarial` | x86 | 15 мин | **да — по `IFR`** |
| Сравнение с golden, допуск 5% | x86 | 1 мин | да |
| **Итого** | | **~55 мин** | |

> Кросс-сборка стоит в блокирующих намеренно. Ошибка сборки под ARM, обнаруженная через неделю, стоит в разы дороже 10 минут в PR.

## 3. Правила прохождения

| Условие | Действие |
|---|---|
| Любой тест уровня 0 упал | merge заблокирован |
| `IFR` вырос более чем на 0.1 п.п. относительно golden | **merge заблокирован**, независимо от остального |
| Любая ключевая метрика упала более чем на 5% | merge заблокирован |
| Кросс-сборка aarch64 упала | merge заблокирован |
| Ночной прогон уровня B упал | issue заводится автоматически, merge не блокируется |
| Сценарий Isaac S-04 или S-05 упал | **релиз заблокирован**, в поле не выходим |
| Тест недетерминирован (разный результат на одном сиде) | считается сломанным, чинится как обычный баг |

## 4. Артефакты

Каждый прогон сохраняет:

```
artifacts/<pipeline>/<run_id>/
  summary.json           # для машин и трендов
  report.html            # для человека
  results.parquet        # сырые данные для послеанализа
  failures/              # худшие случаи с визуализацией
  logs/                  # rosbag2 нарезки вокруг провалов, ulog из Isaac
  bench.json             # только для target=rk3588
```

Срок хранения: `pr` — 14 дней, `nightly` — 90 дней, `release` — бессрочно.

## 5. Тренды

Метрики каждого прогона пишутся в общий parquet-датасет. Дашборд (статический HTML, генерируется в `nightly`) показывает:

- `A@20`, `IFR`, `acceptance_rate` во времени, по коммитам;
- латентность p95 на плате во времени — **это ловит постепенную деградацию рантайма**, которую разовый прогон не заметит;
- разбивку по классам местности во времени;
- температуру и частоты платы.

> Тренд важнее одиночного прогона. Медленное сползание `IFR` с 0.2% до 0.45% не уронит ни один отдельный тест, но означает, что что-то ломается.

## 6. Кэширование и скорость

| Что | Как |
|---|---|
| Docker-слои | Registry cache, отдельный слой под зависимости ROS |
| Тайлы подложки | Персистентный кэш на раннере, не качаются заново |
| Датасеты | Смонтированы с NAS / локального диска, не качаются в CI |
| Модели RKNN | Артефакт сборки, конвертируются только при изменении модели |
| Сборка | `ccache` / `sccache` |

**Цель:** PR-пайплайн ≤60 минут. Если растёт — резать наборы уровня A, а не отключать `adversarial`.

## 7. Деплой на плату

```
кросс-сборка в Docker (--platform linux/arm64)
        │
   образ-артефакт (tar) ──► rsync на OrangePi
        │
   systemd: остановка → распаковка → запуск → healthcheck
        │
   healthcheck: все узлы поднялись, /geoloc/status публикуется, FAST-LIVO2 ≥10 Гц
        │
   при провале — автоматический откат на предыдущий образ
```

Тот же механизм используется для полевого развёртывания — это не отдельный процесс, и это принципиально: в поле летит **ровно тот образ, что прошёл CI**.
