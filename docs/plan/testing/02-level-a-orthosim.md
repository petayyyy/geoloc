# 02 — Уровень A: OrthoSim

**Роль:** основной инструмент разработки и регрессии. Гоняется на каждый коммит, на CPU, детерминированно.
**Задачи:** T10 (v1), T11 (v2), T12 (метрики).

---

## 1. Идея

Мы не симулируем физику. Мы **генерируем тестовые пары** «true-ortho патч ↔ окно карты» с точно известным ground truth — потому что GT здесь не измеряется, а задаётся.

```
ортофото провайдера B (запрос)  ──┐
DSM (реальный или синтетический) ─┤
заданная поза камеры (x,y,z,r,p,y)┤──► рендер перспективного кадра
                                  │         │
                                  │    аугментации: радиометрия, тени,
                                  │    сезон, шум, размытие, JPEG
                                  │         │
                                  │    (опц.) синтез облака Avia из DSM
                                  │         │
                                  │    боевой пайплайн true-ortho
                                  │         ▼
ортофото провайдера A (карта) ────┴──► МАТЧИНГ ──► SE(2) ──► сравнение с GT
```

## 2. Ключевой приём: кросс-провайдерный домейн-гэп

Главная ошибка, которую здесь легко допустить, — рендерить запрос из той же подложки, по которой идёт матчинг. Тогда домейн-гэп равен нулю и метрики получаются фантастическими.

Поэтому: **запрос всегда из другого источника, чем карта.**

| Пара | Разница | Что моделирует |
|---|---|---|
| Esri World Imagery ↔ Bing Aerial | Разные даты, сенсоры, обработка | Базовый кросс-доменный разрыв |
| Esri ↔ Mapbox Satellite | Разная радиометрия и резкость | То же |
| NAIP 2021 ↔ NAIP 2023 | Один сенсор, два года | Устаревание карты, изменения застройки |
| Летний снимок ↔ зимний | Сезон | Худший реалистичный случай |
| Sentinel-2 (10 м) ↔ Esri (0.5 м) | Разрешение | Деградация Tier 2 |

Это даёт **натуральный** разрыв — с настоящими различиями в тенях, растительности, застройке и обработке, которые ни один рендерер не воспроизведёт.

## 3. Аугментации поверх

| Группа | Параметры | Диапазон свипа |
|---|---|---|
| Радиометрия | гамма, баланс белого, контраст, дымка | γ 0.7–1.4; ΔWB ±15%; haze 0–0.3 |
| Освещение | направленные тени по DSM (ray-cast), высота солнца | 10° / 30° / 60° / 80° |
| Сезон | подмена источника + цветовой перенос, снежные маски | 0–100% покрытия снегом |
| Геометрия | ошибка attitude, ошибка AGL, ошибка синхронизации | roll/pitch/yaw ±0.1–2.0°; AGL ±0.5–5%; Δt 0–50 мс |
| Сенсор | шум, размытие в движении, виньетирование, JPEG | σ 1–8 LSB; blur 0–3 px; q 60–95 |
| Динамика | движущиеся объекты (машины), поддельные наложения | 0–5% площади |

Все параметры — из YAML-конфига набора, сид фиксирован.

## 4. Синтез облака Avia (v2, задача T11)

Чтобы тестировать **весь** пайплайн, а не только матчер, нужен вход в виде облака точек.

| Свойство | Модель |
|---|---|
| Паттерн сканирования | Non-repetitive «цветок» Avia; либо табличный паттерн, либо аппроксимация розеткой Лиссажу |
| FOV | 70.4° × 77.2° — **обязательно соблюдать**, дефицит покрытия относительно кадра камеры это ключевой тест-кейс |
| Дальность | до 190 м @ 10% отражения; вероятность отсутствия возврата растёт с дальностью и падением отражательной способности |
| Шум дальности | σ ≈ 2 см + пропорциональная составляющая |
| Motion distortion | Точки генерируются вдоль реальной траектории за интервал накопления — **проверка deskew** |
| Отказы | Вода → нет возврата; стекло/тёмные поверхности → пониженная вероятность |

Отсюда рождаются два обязательных теста, которых иначе нигде не будет:
- **A-DSM-01:** доля патча с лидарным покрытием при AGL 100/125/150 м. Ожидание ~70%; если пайплайн этого не отражает — карта уверенности врёт.
- **A-DSM-02:** качество композита DSM на границе «лидар ↔ Copernicus». Скачок высоты на стыке не должен порождать артефакт в true-ortho.

## 5. Наборы

| Набор | Пар | Состав | Время | Такт |
|---|---|---|---|---|
| `smoke` | 200 | 1 район, номинал | ~1 мин | каждый коммит |
| `regression` | 3000 | 6 районов × 4 класса местности × номинал+лёгкая деградация | ~15 мин | каждый PR |
| `sweep_altitude` | 1500 | AGL 80/100/125/150/200 м | ~20 мин | ночной |
| `sweep_domain` | 2500 | кросс-провайдер × сезон × угол солнца | ~30 мин | ночной |
| `sweep_degradation` | 2000 | attitude, AGL, синхронизация, шум | ~20 мин | ночной |
| `adversarial` | 1200 | см. ниже | ~15 мин | каждый PR |

### Набор `adversarial`

Существует не чтобы система его прошла, а чтобы измерить, **как часто она уверенно ошибается**.

| Сцена | Ловушка |
|---|---|
| Регулярная сельхозсетка, теплицы | Периодичность → корректный, но сдвинутый на период матч |
| Ряды одинаковых складов / ангаров | То же |
| Открытая вода, водохранилище | Нет структуры; матчер обязан отказаться, а не выдумать |
| Сплошной снег | То же |
| Свежая застройка (карта старше на 2 года) | Матч по исчезнувшим объектам |
| Лес без просек | Текстура есть, но она не повторяется между источниками |
| Симметричные развязки и перекрёстки | Матч с поворотом на 90°/180° |

**Целевой критерий:** на `adversarial` доля **принятых** фиксов с ошибкой >50 м **< 0.5%**. Доля отказов при этом может быть какой угодно высокой — это нормально и правильно.

## 6. Выход

```
runs/<timestamp>_<git_sha>_<set>/
  config.yaml            # полный конфиг с сидом
  results.parquet        # по строке на пару: GT, оценка, все метрики качества
  summary.json           # агрегаты для CI
  report.html            # графики: recall-кривые, error CDF, error vs параметр свипа
  failures/              # худшие 50 случаев: патч, окно карты, соответствия, оценка
```

Директория `failures/` обязательна. Отладка матчинга без визуального разбора конкретных провалов не работает.

## 7. Контракт с боевым кодом

> **Правило:** OrthoSim подаёт данные в **тот же самый** код, что работает на борту. Никаких «упрощённых версий для тестов».

Реализация: генератор пишет ROS 2 bag либо вызывает те же библиотечные функции, что и узлы. Второй путь быстрее и предпочтителен для `smoke`/`regression`; первый обязателен для набора с синтезом облака.
