# 01 — Стратегия тестирования (утверждено)

Обоснование выбора и разбор отклонённых вариантов — в `00-simulation-options.md`.

---

## 1. Принятый состав

| Уровень | Что это | Где исполняется | Такт запуска |
|---|---|---|---|
| **Уровень 0** | Юнит- и property-тесты | x86 CI | каждый коммит |
| **Уровень A** | **OrthoSim** — собственный офлайн-генератор пар | x86 CI (CPU) | каждый коммит |
| **Уровень B** | **Реплей** реальных датасетов через боевой ROS 2-граф | x86 + **OrangePi 5 Pro** | ночной / по тегу |
| **Уровень E** | **Isaac Sim + PX4 SITL** — замкнутый контур и фотореалистичные свипы | GPU-машина (RTX 4090) | ночной / перед КТ |
| **Уровень F** | Полевые испытания | Реальный аппарат | по программе T36 |

**HIL — не уровень, а способ исполнения.** FAST-LIVO2 уже работает на плате по bag, поэтому уровни A и B прогоняются и на x86 (быстро, для разработки), и на OrangePi (медленно, для правды о рантайме). Различие фиксируется тегом прогона `target=x86|rk3588`.

**Gazebo** остаётся как опциональный быстрый smoke-тест контура на существующем стенде (T30-opt). Вкладываться в Livox-плагин под него **не нужно** — эти прогоны проверяют MAVROS-мост и режимы, а не лидар.

## 3. Правило «одна метрика — один уровень»

Чтобы не было спора о том, чьей цифре верить, каждая метрика имеет **один авторитетный источник**:

| Метрика | Авторитетный уровень | Остальные уровни |
|---|---|---|
| A@5/10/20/50 м, курсовая ошибка фикса | **B** (MARS-LVIG) | A — для регрессии и тюнинга, не для отчёта |
| Integrity failure rate | **B**, подтверждается **E** (инъекция) | A — нижняя граница |
| ATE траектории, фиксов/км | **B** | |
| Поведение EKF2, failsafe, задержки | **E** | |
| Устойчивость к углу солнца, сезону, погоде | **E** (управляемо) + **A** (кросс-провайдер, натурально) | |
| Латентность, троттлинг, память | **B с `target=rk3588`** | |
| Корректность геометрии, преобразований | **0** | |

## 4. Уровень 0 — юнит и property

| Что | Инструмент |
|---|---|
| Преобразования координат WGS84 ↔ ENU ↔ пиксели | `hypothesis`: round-trip с допуском 1e-6 |
| Backward-projection орторектификации | Property: варп → обратный варп = исходник, RMS < 0.1 px |
| Нормализация углов, композиция SE(2) | Property: ассоциативность, обратимость, `[-π,π]` |
| Оценка SE(2) из синтетических соответствий | Известная трансформация восстанавливается с ошибкой < 1e-3 |
| Парсинг и запись `.geopack` | Round-trip манифеста, границ, георефернции |
| Ковариация: положительная определённость, симметрия | Инвариант, проверяется на каждом вызове в debug-сборке |

Порог покрытия: **≥80% для пакетов `geoloc_ortho`, `geoloc_matcher`, `geoloc_integrity`, `geoloc_fusion`**. Для драйверов и мостов — без требования.

## 5. Уровень A — OrthoSim

Подробности — `02-level-a-orthosim.md`.

Суть: тестовая пара «запрос ↔ карта» генерируется из **разных источников снимков** (Esri / Bing / Mapbox / NAIP разных лет), запрос варпится по заданной 6-DoF позе через DSM, поверх накладываются радиометрические и геометрические искажения. GT известен точно, потому что задан.

Обязательные наборы:

| Набор | Содержание | Размер | Когда |
|---|---|---|---|
| `smoke` | 200 пар, один район, номинальные условия | ~1 мин | каждый коммит |
| `regression` | 3000 пар, 6 районов × 4 класса местности | ~15 мин | каждый PR |
| `sweep_altitude` | AGL 80/100/125/150/200 м | ~20 мин | ночной |
| `sweep_domain` | Кросс-провайдер × сезон × угол солнца | ~30 мин | ночной |
| `sweep_degradation` | Ошибки attitude 0.1–2°, AGL 0.5–5%, синхронизации 0–50 мс | ~20 мин | ночной |
| `adversarial` | Повторяющиеся структуры, вода, снег, свежая застройка — **для замера integrity FR** | ~15 мин | каждый PR |

Набор `adversarial` — самый важный. Он существует не чтобы система его прошла, а чтобы измерить, **как часто она уверенно ошибается**.

## 6. Уровень B — реплей

Подробности — `03-level-b-replay.md`.

| Датасет | Роль |
|---|---|
| MARS-LVIG | Основной. Лидар + надирная камера + RTK, 80–130 м, до 7.148 км |
| UAVScenes | Семантический канал, 6-DoF позы |
| OrthoLoC | Матчинг true-ortho ↔ DOP, валидация AdHoP |
| AnyVisLoc / UAV-AVL | Сравнение Tier1/Tier2, только матчер |
| UAV-VisLoc, VPAIR | Дополнительные сцены |

Прогон **через боевой ROS 2-граф**, не через отдельный скрипт. Разница принципиальна: реплей должен ловить ошибки интеграции, QoS, таймстампов и tf, а не только алгоритма.

## 7. Уровень E — Isaac Sim

Подробности — `04-level-e-isaac.md`.

Сценарии обязательные к прохождению перед выходом в поле:

| ID | Сценарий | Критерий |
|---|---|---|
| S-01 | Номинальный полёт 5 км по коридору | ATE ≤ 15 м, режим NOMINAL ≥90% времени |
| S-02 | Холодный старт с приором ±500 м | Первый фикс ≤10 с, сходимость курса ≤2 км |
| S-03 | Потеря фиксов на 3 км (пролёт над водой) | Переход в COASTING, ошибка на выходе ≤ 60 м, восстановление ≤30 с |
| S-04 | **Инъекция ложного фикса** (сдвиг 150 м) | Отвергнут integrity. Ни одного попадания в EKF2 |
| S-05 | Инъекция серии из 3 согласованных ложных фиксов | Отвергнуты либо ограничены по влиянию; ошибка позы не выросла >30 м |
| S-06 | Kidnapped robot: телепорт на 2 км | Переход в LOST, восстановление ≤120 с либо честный отказ |
| S-07 | Деградация лидара (50% точек) | DSM-покрытие падает, ковариация растёт, ложных фиксов нет |
| S-08 | Свип угла солнца 10°/30°/60° | Деградация доступности фиксов документирована, не обрыв |
| S-09 | Задержка контура +200 мс | EKF2 не расходится |
| S-10 | Перезапуск узла geoloc в полёте | Восстановление ≤20 с, без скачка позы >10 м |

**S-04 и S-05 — блокирующие.** Провал любого из них означает «в поле не выходим».

## 8. Fault injection

Единый механизм для всех уровней: узел-прокси, подменяющий или искажающий сообщения по сценарию из YAML.

| Инъекция | Параметры |
|---|---|
| Пропадание фиксов | длительность, момент |
| Ложный фикс | смещение, курс, «правдоподобные» метрики качества |
| Окклюзия камеры | доля кадра, длительность |
| Деградация лидара | доля точек, шум дальности |
| Скачок / дрейф AGL | амплитуда, скорость |
| Шум и bias IMU | по модели |
| Задержки и джиттер | по топикам |
| Разрыв tf | длительность |

Сценарий описывается декларативно, привязывается к времени или пройденному пути, воспроизводим по сиду.

## 9. Регрессия и golden runs

| Механизм | Описание |
|---|---|
| Golden runs | Зафиксированный набор прогонов (A: `regression`, `adversarial`; B: три нарезки MARS-LVIG по 500 м) с сохранёнными метриками |
| Допуски | Падение CI при ухудшении любой ключевой метрики более чем на **5% относительно golden** |
| Обновление golden | Только явным коммитом с обоснованием в описании PR. Автоматическое обновление запрещено |
| Детерминизм | Все прогоны с фиксированным сидом. Недетерминированный тест считается сломанным тестом |

## 10. Monte-Carlo и состоятельность фьюжна

Отдельный набор для `geoloc_fusion`: ≥100 прогонов с разными сидами шума.

| Проверка | Критерий |
|---|---|
| **NEES** (нормализованная ошибка оценки) | Средняя лежит в 95% доверительном интервале χ² по числу степеней свободы |
| **NIS** (нормализованная инновация) | Аналогично, для последовательности фиксов |
| Доля времени внутри 1σ | 60–75% (теория — 68%) |
| Доля времени внутри 3σ | ≥ 99% |

> Это единственный способ узнать, честна ли ковариация. А от честности ковариации напрямую зависит `eph`, а от него — доверие EKF2. Если NEES вылетает — виноват T21, и чинить надо там, а не подкручивать константы в `geoloc_mavlink`.
