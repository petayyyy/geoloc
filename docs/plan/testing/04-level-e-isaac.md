# 04 — Уровень E: Isaac Sim + PX4 SITL

**Роль:** замкнутый контур и управляемые фотореалистичные свипы. Единственный уровень, где проверяется поведение автопилота.
**Задачи:** T28 (сцена и RTX-Lidar), T29 (терраин из DEM), T30 (сценарии и fault injection).
**Железо:** GPU-машина с RTX 4090.

---

## 1. Почему Isaac, а не Gazebo

| | Gazebo Harmonic | Isaac Sim |
|---|---|---|
| Модель Livox Avia | Нужен плагин под non-repetitive scan; существующие форки под старые версии | **RTX Lidar с конфигурационным профилем** — паттерн задаётся JSON, писать плагин не нужно |
| Дальность лидара | Текущий стенд: 30 м — бесполезно на 100–150 м | Ограничений нет |
| Фотореализм / освещение | Слабый, свип по солнцу малоосмыслен | Path tracing, физически корректное солнце и небо — **свипы имеют смысл** |
| Терраин из DEM + ортотекстура | Heightmap, просто | DEM → USD mesh, чуть сложнее, но качественнее |
| PX4 SITL | Нативно | Через ROS 2-мост / PX4 Isaac integration |
| CI | Headless, дёшево | Требует RTX на каждый прогон |

Isaac закрывает разом замкнутый контур **и** фотореалистичный свип — то есть два варианта из исходного разбора. Ценой того, что per-commit CI на нём невозможен.

> **Следствие для CI:** per-commit остаётся на уровне A (OrthoSim, CPU). Isaac — **ночной прогон** и обязательный прогон перед контрольными точками КТ-5 и КТ-6.

**Существующий Gazebo-стенд** сохраняется как опциональный быстрый smoke-тест MAVROS-моста и переключения режимов (T30-opt). Вкладываться в Livox-плагин под него не нужно: 30-метровый лидар для этих прогонов не мешает, потому что они не про лидар.

## 2. Сцена

```
Copernicus DEM 30 м ──► ресемплинг ──► USD mesh терраина
                                            │
спутниковая ортотекстура @ 0.3–0.5 м ───────┤ (albedo)
                                            │
(опц.) 3D-ассеты: здания из OSM footprints ─┤ ← даёт настоящий параллакс
       растительность, дороги                │
                                            ▼
                                      сцена коридора 10 × 2 км
                                            │
                        физическое солнце (азимут/высота/дата) + небо + погода
```

**Ключевой момент про домейн-гэп.** Если текстурировать терраин той же подложкой, по которой матчимся, гэп равен нулю и метрика точности бессмысленна. Поэтому:

> **Правило E-1.** Терраин в Isaac текстурируется подложкой **провайдера B**. Матчинг идёт по подложке **провайдера A**. Это то же правило, что в OrthoSim, и оно обязательно.

Дополнительно: 3D-здания из OSM footprints с экструзией дают настоящий параллакс и окклюзии — то, чего OrthoSim принципиально не умеет. Это уникальный вклад уровня E в проверку геометрии (R2).

## 3. RTX Lidar под Livox Avia

| Параметр | Значение |
|---|---|
| FOV | 70.4° (H) × 77.2° (V) |
| Паттерн | Non-repetitive, розетка. Задаётся конфигурационным профилем RTX Lidar |
| Дальность | 190 м @ 10% отражения; кривая вероятности возврата от отражательной способности |
| Частота точек | ~240 000 точек/с (соответствует Avia) |
| Шум | Гауссов по дальности, σ ≈ 2 см + пропорциональная составляющая |
| Motion distortion | **Обязательно включить** — иначе deskew не тестируется |
| Формат вывода | `livox_ros_driver2/CustomMsg`, чтобы FAST-LIVO2 не отличал от реального |

> **Важная оговорка.** Результаты FAST-LIVO2 в симуляции **на реальность не переносятся**: нет реальной интенсивности, атмосферы, многолучёвости, паразитных отражений. Одометрия валидируется на MARS-LVIG (уровень B). Лидар в Isaac нужен, чтобы граф работал целиком и чтобы тестировать покрытие DSM и deskew — не чтобы мерить точность одометрии.

## 4. Сценарии

| ID | Сценарий | Критерий прохождения | Блокирующий |
|---|---|---|---|
| S-01 | Номинальный полёт 5 км по коридору | ATE ≤ 15 м; режим NOMINAL ≥90% времени | да |
| S-02 | Холодный старт, приор ±500 м | Первый фикс ≤10 с; курс сходится в пределах 2 км | да |
| S-03 | Потеря фиксов 3 км (пролёт над водой) | COASTING; ошибка на выходе ≤60 м; восстановление ≤30 с | да |
| **S-04** | **Инъекция одиночного ложного фикса (сдвиг 150 м)** | **Отвергнут. Ни одного попадания в EKF2** | **да** |
| **S-05** | **Серия из 3 согласованных ложных фиксов** | **Отвергнуты либо влияние ограничено; рост ошибки ≤30 м** | **да** |
| S-06 | Kidnapped robot: телепорт на 2 км | LOST; восстановление ≤120 с либо честный отказ без ложных фиксов | да |
| S-07 | Деградация лидара до 50% точек | Покрытие DSM падает, ковариация растёт, ложных фиксов нет | да |
| S-08 | Свип угла солнца 10° / 30° / 60° / 80° | Доступность фиксов деградирует плавно, документировано | нет |
| S-09 | Задержка контура +200 мс | EKF2 не расходится; `EKF2_GPS_DELAY_MS` компенсирует | да |
| S-10 | Перезапуск узла `geoloc_fusion` в полёте | Восстановление ≤20 с, скачок позы ≤10 м | да |
| S-11 | Свип погоды: ясно / дымка / лёгкая облачность | Документирована граница работоспособности | нет |
| S-12 | Полёт над однородным полем 2 км | Основной канал падает, включается резерв; ковариация честно растёт | нет |

**S-04 и S-05 — абсолютно блокирующие.** Провал любого = в поле не выходим. Это единственные тесты, проверяющие главный предохранитель системы в реальном контуре.

## 5. Fault injection

Единый механизм со всеми уровнями: узел-прокси между `geoloc_integrity` и `geoloc_fusion` (либо между `geoloc_mavlink` и MAVROS), подменяющий сообщения по декларативному сценарию.

```yaml
# scenarios/S-05-consistent-false-fixes.yaml
seed: 42
trigger: {type: distance, value_m: 1500}
injections:
  - type: false_fix
    count: 3
    interval_s: 1.0
    offset: {east: 120.0, north: -90.0, yaw_deg: 2.5}
    fake_quality:                 # правдоподобные метрики — самый злой вариант
      n_inliers: 84
      covisibility: 0.41
      peak_ratio: 1.9
      residual_rms_px: 0.8
expect:
  accepted_false_fixes: 0
  max_position_error_growth_m: 30.0
```

## 6. Прогон и отчёт

| | |
|---|---|
| Запуск | `make sim-scenario ID=S-04 SEED=42` |
| Детерминизм | Фиксированный сид физики, шума сенсоров и инъекций. Недетерминированный сценарий = сломанный сценарий |
| Длительность | S-01 ~10 мин real-time; допускается ускорение, если PX4 SITL держит lockstep |
| Выход | Логи PX4 (ulog), rosbag2, `results.json`, видео пролёта для разбора |
| Отчёт | Таблица «сценарий × прошёл/не прошёл × метрики», с трассой каждого провала |

## 7. Что уровень E НЕ даёт

- **Прогноз точности для поля.** Домейн-гэп здесь синтетический и управляемый. Число точности из Isaac нельзя выдавать за прогноз — его даёт только уровень B.
- **Оценку FAST-LIVO2.** См. оговорку в §3.
- **Рантайм-метрики.** Симуляция идёт на x86+RTX, не на RK3588.
