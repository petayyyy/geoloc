# ADR — журнал архитектурных решений

Каждое значимое решение записывается здесь: контекст, варианты, выбор, последствия и **условие пересмотра**. Последнее важнее всего: решение без явного триггера пересмотра со временем превращается в догму, которую никто не помнит, зачем приняли.

## Шаблон

```markdown
# ADR-NNN — Название

**Статус:** Предложено / Принято / Заменено ADR-XXX / Отклонено
**Дата:** YYYY-MM-DD
**Связанные задачи:** TXX, TYY

## Контекст
Что за проблема, какие ограничения, что известно на момент решения.

## Варианты
Таблица: вариант — за — против.

## Решение
Что выбрано и почему именно это.

## Последствия
Что становится проще, что сложнее, какие задачи это порождает.

## Условие пересмотра
Конкретное наблюдение, при котором решение пересматривается.
```

## Правила ведения

- ADR **не редактируется** после принятия. Изменение решения — это новый ADR со статусом «Заменяет ADR-NNN», старый получает «Заменено ADR-MMM».
- Отрицательный результат — тоже решение. Если T18 (AdHoP) или T34 (файн-тюн) не дают выигрыша, это фиксируется ADR с числами, а не забывается.
- Открытые ADR (007, 008) должны быть закрыты до старта зависящих от них задач.
