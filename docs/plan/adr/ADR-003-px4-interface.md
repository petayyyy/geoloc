# ADR-003 — Интерфейс с PX4: `GPS_INPUT`

**Статус:** Принято
**Связанные задачи:** T25, T26, T27

## Контекст

Глобально скорректированную позу нужно передать в PX4 так, чтобы EKF2 её корректно использовал. Два штатных пути: `VISION_POSITION_ESTIMATE` (для визуальной одометрии) и `GPS_INPUT` (внешний источник GNSS).

Известная проблема: issue hku-mars/FAST-LIVO2 #126 — при подаче позы через `/mavros/vision_pose/pose` в режиме Position дрон существенно дрейфует, EKF2 расходится («when switching to Position mode, the drone... experiences significant drift without any manual input»).

## Варианты

| Вариант | За | Против |
|---|---|---|
| **`GPS_INPUT`** | EKF2 работает в режиме, для которого спроектирован и отлажен. Ковариация передаётся штатными полями `eph`/`epv`. Понятная деградация через `fix_type` | Требует ослабления `EKF2_GPS_CHECK`. Нужно синтезировать `satellites_visible`, `hdop`/`vdop` |
| `VISION_POSITION_ESTIMATE` | Семантически честнее — это и есть визуальная оценка | **Наблюдаемый дрейф EKF2.** Vision-канал рассчитан на локальную, а не глобальную привязку |
| Оба одновременно | — | Два коррелированных источника одной величины; EKF2 занизит совместную неопределённость |
| Свой EKF на борту, в PX4 — только команды | Полный контроль | Дублирование фильтра, рассогласование с внутренним состоянием PX4, несовместимость с failsafe-логикой автопилота |

## Решение

**Подаём через `GPS_INPUT`.** Полный контракт полей — `03-interfaces.md` §3.

Ключевые правила:
- `time_usec` — время **кадра**, не публикации; задержка контура компенсируется здесь;
- `eph`/`epv` — **напрямую из ковариации, без сглаживания**;
- `fix_type` понижается по режимам: `NOMINAL` → 3, `CONVERGING`/`COASTING` → 2 → 1, `LOST` → 0;
- скоростные поля игнорируются — скорость даёт FAST-LIVO2 своим каналом;
- `EKF2_GPS_DELAY_MS` выставляется по **измеренной** задержке, не по умолчанию.

## Последствия

**Осознанно принимаемый риск:** ослабление `EKF2_GPS_CHECK` снимает последнюю защиту автопилота от плохих измерений и **полностью перекладывает ответственность на наш integrity monitor** (T22). Это прямое следствие данного решения и главная причина, по которой `IFR < 0.5%` является блокирующим требованием, а сценарии S-04/S-05 — блокирующими тестами.

**Требует:** честной ковариации (T21). Проверка состоятельности — доля времени, когда истинная ошибка внутри `eph`, ≈68% — становится обязательным критерием приёмки T26.

**Требует:** измерения задержки контура. Ошибка 200 мс на 15 м/с — это 3 м систематики, растущей со скоростью.

**Ограничивает:** наш узел не принимает решений о полёте (см. T27). Failsafe остаётся за PX4 и оператором.

## Условие пересмотра

| Наблюдение | Действие |
|---|---|
| В новой версии PX4 поведение EKF2 на `VISION_POSITION_ESTIMATE` исправлено | Пересмотреть; vision-канал семантически честнее и не требует ослабления проверок GNSS |
| EKF2 отвергает наши фиксы несмотря на корректные `eph` и `satellites_visible` | Разбор инноваций: почти всегда причина — преобразование координат либо неучтённая задержка, а не сам интерфейс |
| Появление в PX4 штатного канала для внешней глобальной привязки с ковариацией | Перейти на него |
