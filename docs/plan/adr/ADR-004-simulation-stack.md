# ADR-004 — Стек тестирования: уровни A + B + E

**Статус:** Принято
**Связанные задачи:** T10, T11, T08, T09, T28, T29, T30
**Полный разбор вариантов:** `../testing/00-simulation-options.md`

## Контекст

Нужен набор инструментов, закрывающий десять рисков проекта (R1–R10 в `testing/00-simulation-options.md` §1). Рассматривались восемь вариантов: собственный офлайн-рендерер, реплей датасетов, Gazebo Harmonic + PX4 SITL, Blender/Cycles, Isaac Sim, AirSim/Colosseum, Flightmare и HIL на плате.

Существенное обстоятельство: **FAST-LIVO2 уже запущен на OrangePi 5 Pro по bag**, поэтому экзистенциальный риск R8 («влезает ли вообще») снят до начала работ.

## Решение

| Уровень | Что | Такт запуска |
|---|---|---|
| **0** | Юнит- и property-тесты | каждый коммит |
| **A** | **OrthoSim** — собственный генератор пар | каждый коммит, x86 CPU |
| **B** | **Реплей** реальных датасетов через боевой ROS 2-граф | ночной, x86 **и OrangePi** |
| **E** | **Isaac Sim + PX4 SITL** | ночной, GPU-машина |
| F | Полевые испытания | по программе T36 |

**HIL — не уровень, а способ исполнения.** Уровни A и B прогоняются и на x86, и на плате; различие фиксируется тегом `target=x86|rk3588`.

**Отклонены:** Gazebo как основной (см. ниже), Blender (Isaac закрывает), AirSim/Colosseum (заархивирован, слабая модель лидара), Flightmare/FlightGoggles (нет георефернцированного терраина и лидара).

## Обоснование ключевых выборов

**Isaac Sim вместо Gazebo + Blender.** Isaac закрывает **и** замкнутый контур, **и** управляемый фотореалистичный свип по солнцу/сезону/погоде — то есть два варианта разом. RTX Lidar принимает конфигурационный профиль для non-repetitive паттерна, поэтому модель Avia — это конфигурация, а не написание плагина под Gazebo. Здания из OSM дают настоящий параллакс и окклюзии, чего OrthoSim принципиально не умеет. Главное возражение против Isaac — необходимость RTX на каждый прогон — снимается наличием 5× RTX 4090.

**Существующий Gazebo-стенд** сохраняется как опциональный быстрый smoke-тест MAVROS-моста и переключения режимов. Вкладываться в Livox-плагин под него не нужно: эти прогоны не про лидар, и 30-метровый лидар им не мешает.

**OrthoSim обязателен, потому что Isaac не может в CI.** Per-commit регрессия должна идти на CPU за минуты. Кроме того, OrthoSim даёт **натуральный** кросс-доменный разрыв через разные источники снимков, чего движок не воспроизведёт.

**Реплей обязателен, потому что он единственный честный.** Цифры точности из Isaac — синтетические; прогноз для поля даёт только уровень B.

## Правило, обязательное для A и E

> **Запрос рендерится из одного источника снимков, карта берётся из другого.**

Текстурировать землю той же подложкой, по которой идёт матчинг, — значит получить нулевой домейн-гэп, фантастические метрики и вскрыть обман через недели. Оба генератора имеют блокирующие автопроверки: `T10-U-04` и `T29-U-03`.

## Последствия

**Правило «одна метрика — один авторитетный уровень»** (`testing/01-test-strategy.md` §3): точность и `IFR` — уровень B; поведение EKF2 и failsafe — уровень E; устойчивость к освещению — E (управляемо) и A (натурально); рантайм — B с `target=rk3588`.

**Дыра, которую надо помнить:** уровень E даёт синтетический домейн-гэп. Число точности из Isaac нельзя выдавать за прогноз для поля.

**Оговорка про FAST-LIVO2:** в симуляции нет motion distortion по реальной модели, реальной интенсивности, атмосферы и многолучёвости. **Результаты одометрии из Isaac на реальность не переносятся** — одометрия валидируется только на MARS-LVIG.

## Условие пересмотра

| Наблюдение | Действие |
|---|---|
| Isaac Sim недоступен или GPU-машина занята | Вернуться к Gazebo Harmonic + доработке Livox-плагина (вариант C исходного разбора) + Blender для свипов |
| Ночной прогон Isaac не укладывается в ночь | Сократить длительность сценариев; свипы (S-08, S-11) перенести в прогон перед контрольными точками |
| Появление симулятора, пригодного для per-commit CI с фотореализмом | Пересмотреть роль OrthoSim |
