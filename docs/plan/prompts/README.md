# Промты для агентов-исполнителей

Промты на английском (лучше воспроизводимость), документы плана — на русском.

---

## Как пользоваться

**Схема запуска одного исполнителя:**

```
[P0-common.md]  +  [PN-<роль>.md]  +  [tasks/TXX-<задача>.md]
      ↓                  ↓                     ↓
 общие правила     контекст роли        конкретная задача
```

Все три файла подаются агенту вместе. `P0` читается **всегда**, без исключений — в нём принципы, нарушение которых ломает проект независимо от роли.

Дополнительно агент должен иметь доступ к:

| Документ | Зачем |
|---|---|
| `03-interfaces.md` | Источник истины по контрактам. Читается при любой задаче, затрагивающей сообщения |
| `01-requirements.md` | Бюджеты. У каждой задачи есть свой |
| `testing/05-metrics.md` | Определения метрик и пороги |
| `02-architecture.md` §3 | Границы ответственности узлов |

## Что промты намеренно не содержат

- **Кода и сигнатур функций.** Промт задаёт контекст, ограничения и подводные камни; реализацию выбирает исполнитель.
- **Дублирования карточек задач.** DoD, тесты и оценки — в `tasks/`. Промт объясняет, *почему* карточка выглядит именно так.
- **Мягких формулировок там, где правило жёсткое.** Правило эскалации T16, блокирующие сценарии S-04/S-05, запрет автообновления golden, запрет команд полёта из нашего узла — сформулированы как запреты, потому что соблазн их обойти возникает именно в тот момент, когда обходить нельзя.

## Если меняется план

Промты ссылаются на документы плана, а не копируют их. При изменении `03-interfaces.md` или порогов в `05-metrics.md` промты править не нужно — они подхватят новое значение через ссылку. Править промт нужно, только если меняется **принцип**: границы ответственности, правило эскалации, приоритет метрик.
