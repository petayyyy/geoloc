## Цель

Единая реализация всех метрик из `../testing/05-metrics.md`, используемая **всеми** уровнями. Одна метрика — одна реализация, иначе цифры разных уровней несопоставимы и спор о том, чьей верить, неразрешим.

## Что реализовать

1. **Библиотека метрик** (Python, вне ROS):
   - уровень фикса: `A@d`, `RE_med/p95`, `IFR`, `acceptance_rate`, все качественные признаки;
   - уровень траектории: `ATE_RMSE`, `lateral_p95`, `convergence_distance`, `fixes_per_2km_initial`, `TTFF`, `max_gap_distance`;
   - состоятельность: `NEES`, `NIS`, `sigma1_coverage`, `sigma3_coverage`;
   - рантайм: латентности по стадиям, загрузка, термика.
2. **Разбивка по классам местности** через классификатор из T06 — обязательная для всех метрик фиксов.
3. **Двойной учёт bias:** метрики выводятся и с вычетом измеренного bias подложки, и без. Обе цифры в отчёте.
4. **`summary.json`** по схеме из `05-metrics.md` §6.
5. **`report.html`:** recall-кривые, CDF ошибки, ошибка vs параметр свипа, разбивка по местности, галерея худших 50 случаев с визуализацией соответствий.
6. **Сравнение с golden** с допусками: 5% общий, 0.1 п.п. по `IFR`.
7. **Тренды:** дозапись в общий parquet, генерация статического дашборда.

## Definition of Done

- [ ] Все метрики из `05-metrics.md` реализованы, каждая — один раз
- [ ] Харнесс потребляет выход уровня A и уровня B одинаково
- [ ] `report.html` генерируется и читается без внешних зависимостей (self-contained)
- [ ] Сравнение с golden работает, допуски применяются согласно правилам
- [ ] Дашборд трендов строится по накопленным прогонам

## Подводные камни

- **`A@d` считается среди принятых фиксов, а не среди всех попыток.** Иначе метрика смешивает точность и доступность, и её нельзя интерпретировать. Доступность — отдельная метрика `acceptance_rate`.
- Средняя по всем классам местности цифра вводит в заблуждение: она смешивает город, где всё работает, и лес, где не работает ничего. Разбивка обязательна везде.
- `NEES` — единственный способ узнать, честна ли ковариация. Он неинтуитивен, но без него `eph` в `GPS_INPUT` будет выдуман, а от него зависит доверие EKF2. Реализовать аккуратно и покрыть тестом на заведомо заниженной ковариации.
- Отчёт должен быть self-contained HTML: он будет пересылаться и открываться без окружения.
