# T22 — Integrity monitor

|---|---|
| Трек | FUSE |
| Волна | W4 |
| Зависит от | T21 |
| Блокирует | T23 |

| Роль | Estimation / Fusion |
| Промт | `../prompts/P4-fusion.md` |

## Цель

Решить по каждому фиксу: принять или отвергнуть. Целевая метрика — `IFR < 0.5%`: доля **принятых** фиксов с ошибкой >50 м.

## Почему это главный предохранитель системы

Пропущенный фикс стоит роста ковариации. Принятый ложный фикс уводит EKF2 и может стоить аппарата. Асимметрия последствий полная, и все компромиссы разрешаются в сторону отказа.

`IFR` — единственная метрика проекта, которая стоит выше точности.

## Что реализовать

### 1. Каскад гейтов

Применяются последовательно, отказ на любом = отказ фикса. Причина отказа записывается.

| Гейт | Порог (стартовый) | Смысл |
|---|---|---|
| `n_inliers` | ≥30 | Статистическая база |
| `inlier_ratio` | ≥0.25 | Отношение сигнал/шум матчинга |
| **`covisibility`** | **≥0.20** | Из OrthoLoC: ниже — резкий рост ошибки |
| **`peak_ratio`** | **≥1.3** | **Главная защита от периодических структур** |
| `residual_rms_px` | ≤2.0 px | Качество подгонки |
| `spatial_spread` | ≥0.4 | Инлаеры не в одном углу |
| `mean_confidence` | ≥0.5 | Не опираемся на DEM-зону целиком |
| **χ²-гейт по невязке** | 3 DoF, 99% → 11.34 | Согласие с приором из фьюжна |

Пороги — **параметры конфигурации**, калибруемые на `adversarial`, а не константы в коде.

### 2. Дифференциация по каналам

Резервные каналы получают ужесточённые пороги и ограничение по `fix_type` (канал 2 — никогда не `fix_type=3`).

### 3. Проверка согласованности N подряд

Одиночный фикс, прошедший все гейты, но противоречащий предыдущим, подозрителен. Реализовать скользящее окно: фикс принимается, если согласуется с предыдущими принятыми в пределах, объяснимых дрейфом одометрии за прошедший путь.

**Режим повышенной строгости** (`INIT`, `LOST`, после долгого `COASTING`): требовать согласия **3 фиксов подряд** перед принятием первого. Это снижает частоту фиксов — компенсируется расширением окна поиска.

### 4. Диагностика

Каждый отказ — с причиной в `/geoloc/status.last_rejection_reason` и в `/geoloc/fix_rejected`. Статистика по причинам отказов в отчёте: она показывает, какой гейт реально работает, а какой лишний.

## Definition of Done

- [ ] Все гейты реализованы, пороги в конфиге
- [ ] **`IFR` < 0.5% на `adversarial`** (уровень A)
- [ ] **`IFR` < 0.5% на MARS-LVIG** (уровень B)
- [ ] На классе «вода» `IFR` = 0 — проверяется корректность отказа, не точность
- [ ] Режим повышенной строгости работает в `INIT` и `LOST`
- [ ] Статистика причин отказов доступна в отчёте
- [ ] Сценарии Isaac S-04 и S-05 пройдены

## Подводные камни

- **Согласованные ложные фиксы — самый опасный случай.** Матчер, устойчиво цепляющийся за неверный пик на периодической структуре, выдаст серию взаимно согласованных ложных фиксов. Проверка согласованности их **не поймает** — они согласованы. Поймать может только `peak_ratio` и χ²-гейт по приору. Сценарий S-05 существует ровно для этого.
- **Слишком строгие гейты тоже провал.** Система, отвергающая всё, формально имеет `IFR=0` и полностью бесполезна. Тест T22-A-04 балансирует.
- Калибровать пороги надо на `adversarial`, а не на `regression`: на хороших данных любые пороги выглядят хорошо.
- Не прятать логику отказов в код. Пороги — конфигурация; они будут меняться после каждого полевого выезда.
- χ²-гейт по приору — обоюдоострый: если фьюжн уже уехал, он начнёт отвергать правильные фиксы и закрепит ошибку. Отсюда режим `LOST` с расширенным окном и ослабленным χ²-гейтом, но ужесточённой проверкой согласованности.
