## Цель

Транслировать глобальную позу с ковариацией в MAVLink `GPS_INPUT` так, чтобы PX4 EKF2 работал в привычном GNSS-режиме.

## Почему `GPS_INPUT`, а не `VISION_POSITION_ESTIMATE`

Известная проблема (issue hku-mars/FAST-LIVO2 #126): при подаче позы через `/mavros/vision_pose/pose` в режиме Position дрон существенно дрейфует — EKF2 расходится. Подача глобально скорректированной позы под видом GNSS переводит EKF2 в режим, для которого он спроектирован и отлажен.

Это решение зафиксировано в `../adr/ADR-003-px4-interface.md`.

## Что реализовать

Полный контракт полей — `../03-interfaces.md` §3. Ключевое:

1. **`time_usec` — время кадра, не публикации.** Задержка контура компенсируется здесь, а не игнорируется.
2. **`eph` / `epv` — напрямую из ковариации**, без сглаживания и без констант:
   `eph = sqrt(σ_e² + σ_n²)`, `epv = σ_up`.
3. **`fix_type` по режиму** из T24: `NOMINAL`/`DEGRADED`(канал 1) → 3; `CONVERGING`/`COASTING` → 2, далее 1 по росту σ; `LOST`/`INIT` → 0.
4. **`satellites_visible`** — синтетически, монотонно по качеству: `clamp(6 + n_recent_fixes, 6, 18)`. EKF2 использует как грубый признак.
5. **`hdop` / `vdop`** — по эмпирической шкале от σ, калибруемой в SITL.
6. **`ignore_flags`** — игнорировать поля скорости: скорость даёт FAST-LIVO2 своим каналом, дублирование внесёт конфликт.
7. **`yaw`** — заполняется только при σ_ψ < 2°, иначе помечается как недоступный.
8. **Ограничение частоты** 5 Гц; при отсутствии новых данных — экстраполяция по одометрии с растущей `eph`.

## Definition of Done

- [ ] `GPS_INPUT` публикуется на 5 Гц, принимается PX4 без ошибок
- [ ] `eph` соответствует ковариации; проверено сравнением с истинной ошибкой в SITL
- [ ] `fix_type` меняется согласно режимам, без дребезга
- [ ] Задержка компенсируется: измеренная задержка контура отражена в `time_usec`
- [ ] Скоростные поля игнорируются, конфликта с FAST-LIVO2 нет
- [ ] Сценарий S-09 (задержка +200 мс) пройден

## Подводные камни

- **`eph` нельзя сглаживать «для красоты».** Резкий рост `eph` при переходе в COASTING — это правда, которую EKF2 должен узнать немедленно. Сглаживание превратит честную ковариацию в ложь.
- **Дублирование скорости** — если и FAST-LIVO2, и `GPS_INPUT` подают скорость, EKF2 получит два коррелированных измерения одной величины и занизит их совместную неопределённость.
- **Задержка контура** по умолчанию в PX4 задана для настоящего GNSS. Наша задержка другая, её надо измерить (T26) и выставить `EKF2_GPS_DELAY_MS`. Оставить по умолчанию значит внести систематическую ошибку, пропорциональную скорости.
- `satellites_visible` может выглядеть косметикой, но PX4 использует его в проверках качества GNSS. Значение ниже порога приведёт к отбраковке всех наших фиксов.
