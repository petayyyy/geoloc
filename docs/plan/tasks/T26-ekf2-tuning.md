## Цель

Настроить PX4 EKF2 так, чтобы он корректно использовал наш синтетический GNSS, и доказать это в замкнутом контуре.

Один из двух участков, где ошибка стоит аппарата. Двойной запас времени и обязательный проход всех сценариев T30.

## Что реализовать

1. **Параметры** (стартовые значения — `../03-interfaces.md` §3):

| Параметр | Что делаем |
|---|---|
| `EKF2_AID_MASK` | GPS включён, optical flow и vision выключены — мы маскируемся под GNSS |
| `EKF2_HGT_MODE` | Range finder (лидар даёт z), согласовать с `EKF2_RNG_*` |
| `EKF2_GPS_CHECK` | Ослабить проверки числа спутников и дрейфа — иначе синтетический GNSS будет отвергнут |
| `EKF2_REQ_EPH` | 25 м (наш p95 — 30 м, порог должен быть выше типичного) |
| `EKF2_REQ_SACC` | Ослабить — точность скорости мы не заявляем |
| **`EKF2_GPS_DELAY_MS`** | **Измеренная задержка контура.** Не оставлять по умолчанию |

2. **Измерение задержки контура:** от момента экспозиции кадра до момента, когда EKF2 применил измерение. Метод — корреляция инноваций EKF2 с известным возмущением.
3. **Калибровка шкалы `hdop`/`vdop`** — эмпирические коэффициенты подбираются здесь, по поведению EKF2.
4. **Проверка состоятельности:** доля времени, когда истинная ошибка лежит внутри `eph`, должна быть ~68%. Если нет — виновата T21, чинить там.
5. **Анализ инноваций EKF2:** нормализованные инновации GPS должны быть в норме. Систематическое смещение инноваций = ошибка в отображении координат или задержке.
6. **Документ настройки:** итоговый набор параметров с обоснованием каждого отклонения от значения по умолчанию.

## Definition of Done

- [ ] Набор параметров зафиксирован и задокументирован с обоснованием
- [ ] Задержка контура измерена, `EKF2_GPS_DELAY_MS` выставлен
- [ ] EKF2 не расходится ни в одном сценарии T30
- [ ] Состоятельность: истинная ошибка внутри `eph` в 60–75% времени
- [ ] Нормализованные инновации GPS в норме, без систематического смещения
- [ ] Сценарии S-01, S-03, S-07, S-09 пройдены

## Подводные камни

- **Ослабление `EKF2_GPS_CHECK` — обоюдоострое.** Проверки существуют, чтобы отбрасывать плохой GNSS. Ослабив их, мы снимаем последнюю защиту автопилота и полностью перекладываем ответственность на наш integrity monitor (T22). Это осознанный выбор, зафиксированный в [ADR-003](../adr/ADR-003-px4-interface.md) и [ADR-006](../adr/ADR-006-integrity-over-accuracy.md).
- **`EKF2_GPS_DELAY_MS` по умолчанию задан для настоящего GNSS-приёмника.** Наша задержка другая. Ошибка в 200 мс на 15 м/с — это 3 м систематического смещения, растущего со скоростью.
- **Систематическое смещение инноваций** почти всегда означает одно из двух: неверное преобразование координат либо неучтённая задержка. Это первое, что надо проверять при любой аномалии.
- Состоятельность `eph` **не чинится в этой задаче**. Если она не сходится — проблема в модели ковариации T21. Соблазн подкрутить коэффициенты здесь велик и приведёт к тому, что ковариация станет ложью, подогнанной под один сценарий.
- Настройка в SITL не переносится в поле один в один. Заложить повторную проверку в программу лётных испытаний (T36).
