# T15 — True-ortho патч, композит с DEM, карта уверенности

| | |
|---|---|
| Трек | PERC |
| Волна | W3 |
| Зависит от | T14, T07 |
| Блокирует | T17, T32 |
| Оценка | 6 дней |
| Риск | **средний** |
| Роль | Perception / Geometry |
| Промт | `../prompts/P3-perception.md` |

## Цель

Превратить перспективный кадр камеры в true-ortho патч в той же проекции и с тем же GSD, что подложка. Это то место, где домейн-гэп устраняется **геометрически, до матчинга** — главная архитектурная идея проекта.

## Что реализовать

1. **Backward-projection орторектификация.** Для каждого пикселя выходной орто-сетки: взять высоту из DSM → спроецировать в кадр камеры через калибровку и позу → билинейно взять яркость. Именно backward, а не forward — forward даёт дыры.
2. **Композит DSM.** Локальный лидарный DSM (T14) там, где есть покрытие; Copernicus DEM (T06) на краях. Переход — плавный, с весами, без ступеньки.
3. **Карта уверенности по пикселям** выходного патча:
   - 255 — лидарное покрытие с высокой плотностью точек;
   - промежуточное — редкое покрытие или зона перехода;
   - низкое — только Copernicus DEM;
   - 0 — нет данных (вне кадра, вода без возвратов, окклюзия).
4. **Обработка окклюзий.** При наличии DSM видно, какие пиксели орто-сетки не видны из камеры (закрыты зданием). Их помечать нулевой уверенностью, а не заполнять чем попало.
5. **Приведение GSD** к GSD карты с корректным антиалиасингом (сначала фильтр, потом децимация — не наоборот).
6. **Публикация `OrthoPatch`** по контракту из `../03-interfaces.md` §1.1, включая `lidar_coverage_ratio`.

## Ключевые решения

| Решение | Значение | Обоснование |
|---|---|---|
| Направление проекции | Backward | Forward оставляет дыры и требует интерполяции рассеянных точек |
| Реализация варпа | **RGA или OpenCL на Mali**, не CPU | Бюджет: 15 мс. На CPU это будет 100+ мс |
| Переход лидар ↔ DEM | Плавный по весам | Ступенька порождает ложный признак ровно на границе |
| Антиалиасинг | Фильтр перед децимацией | Иначе алиасинг создаёт признаки, которых нет на карте |
| Окклюзии | Помечать нулевой уверенностью | Заполнение выдуманными данными хуже, чем отсутствие |

## Definition of Done

- [ ] Патч строится за ≤15 мс на плате (варп на RGA/OpenCL)
- [ ] Карта уверенности корректна: лидарная зона ~70% при AGL 100 м
- [ ] Переход лидар ↔ DEM не даёт видимого артефакта (кейс A-DSM-02)
- [ ] Окклюзии зданий помечаются
- [ ] Round-trip варпа проходит property-тест
- [ ] На городской сцене true-ortho по DSM даёт заметно меньшую ошибку матчинга, чем плоскостное допущение (кейс A-DSM-05)

## Подводные камни

- **Варп на CPU не влезет в бюджет.** RGA умеет перспективные преобразования, но не произвольный per-pixel remap по карте смещений — проверить возможности до того, как архитектура на них завяжется. Запасной путь — OpenCL на Mali. Это ключевая техническая неопределённость задачи; выяснить в первые два дня.
- Ступенька на границе лидар/DEM — коварный дефект: она даёт устойчивый, повторяемый признак, который матчер найдёт и на который обопрётся. Ложный фикс из ниоткуда.
- Антиалиасинг при децимации 0.14 м → 0.5 м обязателен. Простой `resize` без фильтра создаст артефакты, которых на спутнике нет.
- Карта уверенности должна быть **честной**. Соблазн проставить высокую уверенность там, где её нет, приведёт к тому, что T17 и T21 будут доверять мусору.
