## Цель

Второй проход матчинга: оценить гомографию по первичным соответствиям, варпнуть окно карты под патч, переспросить матчер, отобразить результат обратно. Метод из OrthoLoC.

## Ожидаемый выигрыш и оговорка

В OrthoLoC AdHoP даёт улучшение матчинга до +95% и трансляции до +63% (в среднем по матчерам: матчинг +30%, TE/RE −20%; для GIM+DKM TE 0.40 → 0.32 м).

**Но:** там AdHoP компенсирует перспективу, сравнивая перспективный кадр с орто. У нас перспектива уже устранена геометрически в T15, домейн-гэп меньше, и выигрыш будет **меньше заявленного**. AdHoP у нас работает как второй проход по остаточному наклону, ошибке attitude и параллаксу зданий в зоне без лидарного покрытия.

Поэтому задача имеет статус **улучшения, а не необходимости**, и включается по условию.

## Что реализовать

1. Оценка гомографии H по 2D-2D соответствиям первого прохода: нормализованный DLT + RANSAC.
2. Варп окна карты по H под геометрию патча.
3. Повторный матчинг на варпнутой паре.
4. Обратное отображение соответствий по H⁻¹, объединение с первым проходом, финальная оценка SE(2).
5. **Условие включения:** второй проход стоит ~40–60 мс. Включать не всегда, а когда первый проход дал пограничный результат — `n_inliers` в диапазоне 15–40 либо `covisibility` 0.15–0.30. При хорошем первом проходе второй не нужен; при полном провале — не поможет.
6. Флаг в конфиге: `always` / `conditional` / `off`.

## Definition of Done

- [ ] AdHoP реализован, работает в режиме `conditional`
- [ ] На `regression` выигрыш измерен и задокументирован (ожидание: скромный)
- [ ] На пограничных случаях выигрыш заметен: доля принятых фиксов растёт
- [ ] Латентность второго прохода ≤60 мс, включается только по условию
- [ ] Не ухудшает `IFR` — проверено на `adversarial`

## Подводные камни

- **AdHoP может ухудшить `IFR`.** Второй проход по варпнутому изображению даёт больше соответствий — в том числе ложных, если первый проход был неверен. Гомография, оценённая по неверным соответствиям, «подгонит» карту под патч и породит убедительный ложный фикс. Тест T18-A-02 блокирующий.
- Не включать `always` без измерения: 40–60 мс на каждый фикс при такте 2 Гц — заметная доля бюджета.
- Если выигрыш окажется в пределах шума (что вероятно, учитывая, что перспективу мы уже убрали) — честно зафиксировать это в ADR и оставить в режиме `off`. Задача выполнена, даже если результат отрицательный.
