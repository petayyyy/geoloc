## Цель

Измерить, **сколько ресурсов остаётся** на плате при работающем FAST-LIVO2. Ответ определяет реализуемость всего остального.

FAST-LIVO2 уже запущен на OrangePi 5 Pro по bag — значит, экзистенциальный вопрос «влезает ли вообще» снят. Остался количественный: что можно потратить на geoloc.

**Это первая задача проекта.** Она не требует ни симулятора, ни матчера, ни карты — только плату, датасет и профайлер. Три дня, и вся команда знает, в каком бюджете работает.

## Что измерить

1. **FAST-LIVO2 в установившемся режиме:**
   - загрузка по ядрам, раздельно A76 и A55;
   - реальный такт и его стабильность (пропуски, джиттер);
   - RSS и её рост со временем;
   - зависимость от плотности облака и сцены.
2. **Свободные ресурсы:**
   - сколько ядер A76 и A55 остаётся;
   - NPU — свободен полностью (FAST-LIVO2 его не использует), измерить пропускную способность трёх ядер;
   - GPU Mali — измерить доступную производительность OpenCL;
   - RGA — **проверить, поддерживает ли per-pixel remap** по карте смещений, а не только аффинные и перспективные преобразования. Это ключевой вопрос для T15;
   - пропускная способность памяти — при одновременной работе LIVO2 и матчера она может стать узким местом раньше, чем вычисления.
3. **Термика:**
   - температура SoC при 30-минутной работе FAST-LIVO2 в текущем корпусе/охлаждении;
   - реальные частоты кластеров — есть ли троттлинг уже сейчас;
   - потребление платы.
4. **Синтетическая нагрузка geoloc:** заглушка, эмулирующая ожидаемую нагрузку матчера (NPU-инференс тестовой модели + матричные операции), запущенная параллельно с FAST-LIVO2. Измерить взаимное влияние.

## Definition of Done

- [ ] Отчёт с профилем FAST-LIVO2: загрузка, такт, память, термика
- [ ] Остаточный бюджет измерен по каждому ресурсу
- [ ] **Ответ по RGA:** поддерживает ли per-pixel remap. Записан в ADR
- [ ] Пропускная способность NPU и GPU измерена
- [ ] Взаимное влияние LIVO2 и синтетической нагрузки измерено
- [ ] Термика за 30 мин: есть троттлинг или нет
- [ ] **Вердикт по КТ-0** с рекомендациями

## Критерий КТ-0 и что делать при провале

| Наблюдение | Решение |
|---|---|
| Остаток ≥1 ядра A76 + 2 ядра NPU | **Идём по плану.** Бюджет из `../01-requirements.md` §5.2 реалистичен |
| Остаток 0.5–1 ядра A76 | Снизить такт фиксов до 1 Гц; варп обязательно на RGA/OpenCL; XFeat вместо XFeat* |
| **Остаток < 0.5 ядра A76** | Такт фиксов 0.5 Гц; матчинг только на ключевых точках маршрута; **рассмотреть перенос на Jetson Orin Nano** |
| Троттлинг уже при одном FAST-LIVO2 | Охлаждение — задача первого приоритета (T33 поднимается в W1), иначе всё остальное бессмысленно |
| RGA не умеет per-pixel remap | T15 идёт через OpenCL на Mali; заложить дополнительное время и измерить производительность заранее |
| Память — узкое место | Пересмотреть размеры окна и патча; рассмотреть 16 ГБ версию платы |

## Подводные камни

- **Мерить надо на реальных данных, не на синтетике.** FAST-LIVO2 сильно зависит от сцены: плотная городская застройка нагружает его иначе, чем открытое поле. Отсюда требование трёх разных последовательностей.
- **Короткий прогон не покажет троттлинг.** Минимум 20–30 минут, в том корпусе и с тем охлаждением, что пойдут в поле.
- **Пропускная способность памяти** — недооценённый ресурс. Матчер работает с большими массивами дескрипторов, FAST-LIVO2 — с воксельной картой. Они могут начать конкурировать за шину раньше, чем за ядра.
- **Вопрос по RGA критичен для T15** и должен быть закрыт здесь, а не когда T15 начнётся. Если RGA не умеет нужного, у T15 меняется реализация и оценка.
