## Цель

Воспроизводимая сборка под x86 (разработка) и под aarch64/RK3588 (борт), плюс образ для CI. Нативная сборка на плате — только для отладки, никогда для деплоя.

## Выходы

| Образ | Назначение |
|---|---|
| `geoloc/dev:x86` | Разработка: ROS 2, Eigen, OpenCV, GTSAM, инструменты |
| `geoloc/cross:aarch64` | Кросс-сборка под RK3588. Содержит RKNN Toolkit2, RGA, Mali OpenCL headers |
| `geoloc/ci` | Тот же dev + инструменты тестирования и отчётов |
| `geoloc/runtime:aarch64` | Минимальный рантайм для платы: только то, что нужно для запуска |

## Ключевые решения

| Решение | Значение | Обоснование |
|---|---|---|
| Способ кросс-сборки | `docker buildx --platform linux/arm64` с QEMU | Проще sysroot-подхода, достаточно быстро при ccache |
| RKNN | `rknn-toolkit2` для конвертации **на x86**, `rknn-toolkit-lite2` + `librknnrt.so` в рантайм | Конвертация ONNX→RKNN работает **только на x86** — это ограничение SDK, не наш выбор |
| RGA | Заголовки и `librga.so` из vendor SDK, версия зафиксирована | |
| GPU | Mali OpenCL ICD с платы; версия драйвера фиксируется вместе с образом ОС | |
| Версионирование | Все vendor-библиотеки — с явным тегом версии, никаких `latest` | Vendor-SDK RK3588 ломают совместимость между версиями |

## Что реализовать

1. Многоступенчатые Dockerfile для четырёх образов.
2. `Makefile` с целями: `build-x86`, `build-arm`, `test`, `deploy`, `bench`.
3. Кэширование: registry cache для слоёв, `ccache` в томе.
4. Скрипт деплоя: сборка → tar → rsync на плату → systemd restart → healthcheck → откат при провале.
5. Фиксация версий: `versions.lock` с версиями ROS, RKNN SDK, RGA, драйвера Mali, ядра.

## Definition of Done

- [ ] `make build-arm` собирает весь workspace под aarch64 из чистого состояния
- [ ] Артефакт разворачивается на OrangePi и запускается: граф поднимается, healthcheck зелёный
- [ ] Время инкрементальной кросс-сборки ≤ 3 мин при тёплом ccache
- [ ] `versions.lock` заполнен, воспроизводимость проверена сборкой на другой машине
- [ ] Деплой умеет откат: при провале healthcheck возвращается предыдущий образ

## Подводные камни

- **Конвертация RKNN только на x86.** Это ловушка, на которой теряют дни: пытаются конвертировать на плате, получают невнятную ошибку. Заложить в документацию явно.
- QEMU-сборка под arm64 медленная. Если время выйдет за 25 минут — переходить на нативный arm64-раннер (плата или облачный Ampere).
- Версия драйвера Mali и версия `librknnrt` должны совпадать с тем, что на плате. Рассинхрон даёт падения в рантайме без внятной диагностики.
