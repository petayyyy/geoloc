## Цель

Основной инструмент разработки и регрессии. Генерирует пары «патч-запрос ↔ окно карты» с **точно известным** ground truth — потому что GT здесь задаётся, а не измеряется.

Спецификация — `../testing/02-level-a-orthosim.md`.

## Что реализовать

1. **Рендер запроса.** Заданная 6-DoF поза камеры → перспективный кадр, отрисованный из ортофото по DSM (в v1 — плоскость или Copernicus, полноценный DSM в T11).
2. **Кросс-провайдерное правило.** Запрос рендерится из провайдера B, карта берётся от провайдера A. Строго, без исключений — это главный источник реализма.
3. **Аугментации** по таблице `02-level-a-orthosim.md` §3: радиометрия, освещение, сезон, геометрические ошибки, шум сенсора.
4. **Конфигурация наборов** в YAML: `smoke`, `regression`, `adversarial`, три `sweep_*`.
5. **Вызов боевого кода.** Пары подаются в те же библиотечные функции, что работают на борту. Никаких «упрощённых версий для тестов».
6. **Детерминизм** по сиду — на всех уровнях, включая выбор поз, аугментаций и порядка.

## Набор `adversarial` — реализовать в v1

Он важнее всех остальных, потому что измеряет не точность, а **частоту уверенных ошибок**.

| Сцена | Ловушка |
|---|---|
| Сельхозсетка, теплицы | Периодичность → корректный, но сдвинутый на период матч |
| Ряды одинаковых ангаров | То же |
| Открытая вода | Нет структуры; матчер обязан отказаться |
| Сплошной снег | То же |
| Свежая застройка | Карта старше на 2 года, матч по исчезнувшим объектам |
| Лес без просек | Текстура есть, но не повторяется между источниками |
| Симметричные развязки | Матч с поворотом на 90°/180° |

## Definition of Done

- [ ] Генерируются все шесть наборов из `02-level-a-orthosim.md` §5
- [ ] `smoke` (200 пар) отрабатывает за ≤1 мин на одном ядре
- [ ] `regression` (3000 пар) за ≤15 мин на CI-машине
- [ ] Один сид → побитово идентичный результат
- [ ] Выход по структуре из `02-level-a-orthosim.md` §6, включая `failures/`
- [ ] Кросс-провайдерное правило соблюдено и проверяется автоматически

## Тесты

| ID | Уровень | Что проверяет | Критерий |
|---|---|---|---|
| T10-U-01 | 0 | Корректность GT | Рендер по известной позе → матчинг идеальной парой (одинаковый источник, без аугментаций) → SE(2) восстанавливается с ошибкой ≤0.1 px |
| T10-U-02 | 0 (property) | Round-trip варпа | Варп → обратный варп даёт исходник, RMS ≤0.1 px |
| T10-U-03 | 0 | Детерминизм | Один сид, два прогона → идентичные `results.parquet` |
| T10-U-04 | 0 | **Защита от самообмана** | Автопроверка: если провайдер запроса == провайдер карты, генератор падает с ошибкой |
| T10-U-05 | 0 | Аугментации | Каждая аугментация применяется и измеримо меняет изображение; нулевые параметры дают тождество |
| T10-A-01 | A | Базовая работоспособность | На `smoke` матчер даёт `A@20` ≥ 60% |

## Подводные камни

- **Главная опасность — самообман.** Рендерить запрос из той же подложки, по которой матчимся, значит получить фантастические метрики и потерять месяц до момента, когда это вскроется на уровне B. Тест T10-U-04 стоит в обязательных именно поэтому.
- GT должен быть задан **до** аугментаций и не пересчитываться после. Любая аугментация, меняющая геометрию (ошибка attitude, AGL), меняет **входные данные пайплайна**, а не истину.
- `failures/` — не украшение. Без визуального разбора конкретных провалов отладка матчинга не работает.
- Не строить в v1 полную модель DSM и теней — это T11. v1 должен появиться быстро и начать приносить пользу.
