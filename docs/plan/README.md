# План: глобальная локализация БПЛА по спутниковой картографии

Кодовое имя стека — `geoloc`. Сенсоры: **Livox Avia + одна надирная камера + IMU**, одометрия — **FAST-LIVO2**, борт — **OrangePi 5 Pro (RK3588S)**, автопилот — **Pixhawk 6X / PX4**. Профиль: AGL 100–150 м, маршрут 5–10 км.

> **Статус: полный черновик.** 4 корневых документа, 7 по тестированию, 36 карточек задач, 8 промтов агентов, 8 ADR.
> **Два ADR открыты и должны быть закрыты до старта волны 0:** [ADR-007](adr/ADR-007-ros-distro-os.md) (ROS-дистрибутив и ОС платы — блокирует T01) и [ADR-008](adr/ADR-008-basemap-providers.md) (провайдеры подложки и лицензии — блокирует T05).

## Как запускать агентов

Каждому исполнителю подаются три файла вместе:

```

```

Плюс доступ к `03-interfaces.md`, `01-requirements.md`, `testing/05-metrics.md`. Подробности — [`prompts/README.md`](prompts/README.md).

## Ключевые решения, зафиксированные в плане

| Решение | Где |
|---|---|
| Дрейф положения не главная проблема — **главная угроза курс**. ±3° на 10 км = ~523 м бокового ухода. Отсюда требование ≥5 фиксов на первых 2 км | `00-vision.md` §3 |
| **True-ortho из лидарного DSM** устраняет домейн-гэп геометрически, до матчинга | `00-vision.md` §4.1 |
| FOV Avia (70.4°×77.2°) **у́же кадра камеры** → дефицит покрытия ~30%, композит с Copernicus DEM + карта уверенности | `01-requirements.md` §3 |
| **Приорное окно из ковариации вместо retrieval-сети** | `00-vision.md` §4.2 |
| **SE(2), а не 6-DoF PnP** — на near-planar сцене PnP переопределён и неустойчив | `00-vision.md` §4.3 |
| **`GPS_INPUT`, а не `VISION_POSITION_ESTIMATE`** — обход известного дрейфа EKF2 | `03-interfaces.md` §3 |
| **`IFR` < 0.5%** (доля принятых ложных фиксов) — метрика, стоящая выше точности | `testing/05-metrics.md` §1 |
| Стек тестов: **уровень A (OrthoSim) + B (реплей) + E (Isaac Sim)**. Isaac заменяет Gazebo и Blender | [ADR-004](adr/ADR-004-simulation-stack.md) |
| Кросс-провайдерное правило: **запрос из одного источника снимков, карта из другого** — обязательно на уровнях A и E | `testing/02-level-a-orthosim.md` §2 |

Обоснования — в [`adr/`](adr/README.md). Три решения оформлены с явными условиями пересмотра; [ADR-006](adr/ADR-006-integrity-over-accuracy.md) (integrity выше точности) пересмотру не подлежит без пересмотра целей проекта.

## Контрольные точки

| КТ | Когда | Критерий |
|---|---|---|
| КТ-0 | нед. 2 | Остаточный бюджет ≥1 ядра A76 + 2 ядра NPU |
| КТ-1 | нед. 5 | OrthoSim: `A@20` ≥60%, `IFR` <1% |
| КТ-2 | нед. 8 | MARS-LVIG: **≥5 фиксов на первых 2 км**, σ_ψ → <0.5° |
| КТ-3 | нед. 11 | Полный контур офлайн: ATE ≤15 м на 5 км, `IFR` <0.5% |
| КТ-4 | нед. 14 | Реалтайм на плате: латентность p95 ≤300 мс, FAST-LIVO2 ≥10 Гц, T ≤80 °C |
| КТ-5 | нед. 17 | Все SITL-сценарии, включая **S-04 и S-05** (ложные фиксы) |
| КТ-6 | — | Лётные: 10 км, ошибка p95 ≤30 м |

Полный список задач с зависимостями и оценками — [`04-roadmap.md`](04-roadmap.md) §2.
