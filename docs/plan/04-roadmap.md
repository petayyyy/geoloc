## 4. Волны параллелизма

Внутри волны задачи **независимы и запускаются одновременно**. Переход к следующей волне не требует полного завершения предыдущей — достаточно закрытия конкретных зависимостей.

### Волна 0 — стартуют немедленно, 6 параллельных потоков

| Задача | Кто | Почему сразу |
|---|---|---|
| **T31** Профилирование RK3588 | Платформенщик | **Первая по важности.** FAST-LIVO2 уже работает — надо узнать остаточный бюджет. Ответ определяет реализуемость всего остального |
| **T16** XFeat → RKNN | ML/Embedded | Самая длинная и рискованная задача (12 д). Начинать раньше всех остальных «долгих» |
| T01 Монорепо | Инфраструктурщик | Разблокирует половину графа |
| T05 Загрузчик подложки | Данные | Разблокирует весь трек MAP и DATA |
| T08 Датасеты | Данные | Долгая загрузка, можно начинать фоном |

## 5. Критический путь

```
T13 (5) → T14 (5) → T15 (6) → T17 (6) → T21 (4) → T22 (6) → T23 (7)
        → T25 (4) → T26 (6) → T27 (5) → T36 (15)     ИТОГО ≈ 69 дней
```

**Параллельный рискованный путь:** `T16 (12 д)` — если он сорвётся, T17 встанет, и критический путь удлинится. Поэтому:

> **Правило T16.** Если к 10-му дню работы T16 нет рабочего RKNN-инференса XFeat с приемлемой точностью после INT8, **немедленно** переключаться на план Б (CPU-ONNX XFeat на A76) и продолжать T17 на нём. Порт на NPU становится задачей оптимизации (T32), а не блокером.

**Второй рискованный путь:** `T26 → T27` (EKF2 и failsafe). Единственное место, где ошибка стоит аппарата. На него закладывается двойной запас времени и обязательный проход всех сценариев T30.

## 6. Контрольные точки

| КТ | Когда | Критерий прохождения | Что делать при провале |
|---|---|---|---|
| **КТ-0** | Конец W0 (≈нед. 2) | T31: остаточный бюджет ≥1 ядра A76 + 2 ядра NPU при работающем FAST-LIVO2 @10 Гц | Снизить такт фиксов до 0.5 Гц; вынести варп на RGA; рассмотреть 16 ГБ версию платы |
| **КТ-1** | Конец W2 (≈нед. 5) | На OrthoSim: A@20м ≥ 60%, integrity FR < 1% | Расширить приорное окно ×1.5–2; включить AdHoP; поднять covisibility-гейт |
| **КТ-2** | Конец W3 (≈нед. 8) | На MARS-LVIG офлайн: **≥5 валидных фиксов на первых 2 км**, σ_ψ → <0.5° | Уплотнить фиксы; проверить bias подложки (T09); включить резервный канал |
| **КТ-3** | Конец W4 (≈нед. 11) | Полный контур офлайн: ATE ≤15 м на 5 км, integrity FR <0.5% | Пересмотреть модель ковариации (T21) — почти всегда причина здесь |
| **КТ-4** | Конец W5 (≈нед. 14) | Реалтайм на плате: латентность p95 ≤300 мс, FAST-LIVO2 ≥10 Гц, T≤80°C | T32 оптимизация; снизить GSD патча; уменьшить окно |
| **КТ-5** | Конец W6 (≈нед. 17) | Все SITL-сценарии пройдены, включая инъекцию ложного фикса | Не выходить в поле. Ужесточить integrity |
| **КТ-6** | W7 | Лётные: 5–10 км, ошибка p95 ≤30 м против GNSS-эталона | — |

## 7. Пороги, меняющие решение

| Наблюдение | Решение |
|---|---|
| На MARS-LVIG < 5 фиксов на 2 км | Расширить приорное окно ×1.5–2, включить AdHoP (T18), удерживать covisibility ≥20% |
| XFeat* на RKNN даёт < 30 инлаеров устойчиво | Перенести матчинг на CPU (A76, 12 ядер справятся при 1 Гц) — план Б T16 |
| Курсовой дрейф > 0.5° после сходимости | Уплотнить фиксы; добавить магнитометр Pixhawk как слабый приор курса |
| Георефернционный bias подложки > 8 м (T09) | Ввести онлайн-оценку bias как состояние в графе факторов (расширение T23) |
| Остаточный бюджет CPU < 0.5 ядра A76 (T31) | Такт фиксов 0.5 Гц; матчинг только по ключевым точкам маршрута; рассмотреть перенос на Jetson Orin Nano |
| Integrity FR не опускается ниже 1% | Добавить обязательную согласованность 3 фиксов подряд перед принятием; это снизит частоту фиксов — компенсировать расширением окна |
| Температура SoC > 85 °C в корпусе | Радиатор + принудительный обдув; при невозможности — снизить такт и частоту A76 |
