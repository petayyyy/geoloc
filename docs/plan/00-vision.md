# 00 — Виденье системы

**Проект:** глобальная локализация БПЛА в GNSS-denied среде по спутниковой ортоподложке.
**Кодовое имя:** `geoloc` (далее так называется наш стек).

---

## 1. Задача одной фразой

Дрон летит без GNSS. FAST-LIVO2 даёт гладкую, но дрейфующую локальную одометрию. Наша система периодически «прибивает» эту одометрию к глобальной системе координат, сопоставляя вид с надирной камеры (ортовыпрямленный по лидарному DSM) со спутниковой ортоподложкой, и отдаёт глобально скорректированную позу в PX4.

## 2. Конфигурация

| Компонент | Значение |
|---|---|
| Бортовой компьютер | OrangePi 5 Pro — RK3588S, 4×A76@2.4 + 4×A55@1.8, Mali-G610 MP4, NPU 6 TOPS (3×2 INT8), 8/16 ГБ LPDDR5, NVMe |

| Автопилот | Pixhawk 6X, PX4, EKF2 |
| Одометрия | FAST-LIVO2 (уже запущен на плате по bag) |
| Подложка | Спутниковая орто, GSD 0.3–0.5 м/px, предзагружена на коридор |
| Профиль полёта | AGL 100–150 м, маршрут 5–10 км, скорость 5–15 м/с |

## 3. Главный тезис архитектуры

**Дрейф положения — не проблема. Проблема — курс.**

FAST-LIVO2 на аэросценах MARS-LVIG даёт per-sequence ATE RMSE 0.75–3.25 м на маршрутах до 7.1 км. На 10 км это единицы–десятки метров — внутри любого разумного бюджета. А вот нескорректированная начальная ошибка курса ±3° на прямом маршруте 10 км даёт **~523 м бокового ухода**. Отсюда всё остальное:

- фиксы нужны не столько ради положения, сколько ради **наблюдаемости курса**;
- отсюда требование **≥5 валидных фиксов на первых 2 км** — оно выводится математически, а не берётся с потолка (5 фиксов сбивают ±3° до 0.15–0.2°, т.е. до 26–35 м на 10 км);
- отсюда же приоритет **integrity над количеством**: один принятый ложный фикс с ошибкой курса хуже, чем десять пропущенных.

## 4. Три опоры

### 4.1 True-ortho из лидарного DSM

Мы **не** матчим перспективный кадр с ортофото. Мы накапливаем облако Avia за 0.5–1 с, дескьюим его по одометрии FAST-LIVO2, строим локальный DSM 0.5–1 м и делаем backward-projection орторектификацию кадра по этому DSM. На выходе — true-ortho патч в той же проекции и с тем же GSD, что и подложка.

Это устраняет домейн-гэп **геометрически, до матчинга**. OrthoLoC косвенно это доказывает: весь их домейн-гэп возникает именно из перспективы, и AdHoP (приведение к орто) его снижает — матчинг до +95%, трансляция до +63%.

**Оговорка, которую нельзя забыть:** FOV Avia (70.4°×77.2°) **уже кадра камеры**. На 100 м AGL облако накрывает ~140×155 м, кадр при HFOV 90° — 200×150 м. Локальный DSM не покрывает патч целиком. Решение: накопление за 0.5–1 с (при 10 м/с добавляет 5–10 м вдоль маршрута) + глобальный DEM (Copernicus 30 м) как заполнитель на краях, с пометкой уверенности по пикселям.

### 4.2 Приорное окно вместо retrieval-сети

Ковариация из фьюжна даёт круг неопределённости радиусом R (типично 50–300 м). Матчим только внутри него. Это снимает главную причину, по которой в литературе вводят retrieval-сети (VPR), и экономит на порядок вычислений. Дескрипторы карты считаются только для окна и пересчитываются, когда окно сдвинулось на >30% своего размера.

При холодном старте или потере, когда R велик, окно расширяется, и вот тогда — многогипотезный поиск с ранжированием.

### 4.3 SE(2), а не 6-DoF PnP

Для надирного вида на локально-плоскую местность полная гомография переопределена и неустойчива при малом числе инлаеров. Оцениваем 3–4 DoF: `Δx, Δy, Δψ` (масштаб известен из AGL и DSM). OrthoLoC прямо показывает: при неравномерном распределении корреспонденций (covisibility <20%) PnP «переобучается» на регионы и деградирует. Плюс там же вскрыта f–t_z ambiguity в near-planar аэровиде — ещё один аргумент не оценивать масштаб из матчинга, раз он у нас наблюдаем напрямую.

## 5. Пайплайн

```
Livox Avia ──┐
             ├──► FAST-LIVO2 ──► одометрия (odom frame), 10+ Гц
Камера ──────┤                        │
IMU ─────────┘                        │
   │                                  │
   │  (тот же поток, 1–2 Гц)          │
   ▼                                  │
накопление облака 0.5–1 с + deskew ◄──┘
   │
локальный DSM 0.5–1 м  (+ Copernicus DEM на краях)
   │
true-ortho патч (backward projection), GSD = GSD карты
   │
XFeat* INT8 @ RKNN NPU ──► дескрипторы запроса
   │                             │
   │        приорное окно карты ─┤ (дескрипторы карты, кэш)
   │                             ▼
   │                    матчинг + MAGSAC → SE(2): Δx, Δy, Δψ
   │                             │
   │        [резерв 1] фазовая корреляция по градиентам (log-polar)
   │        [резерв 2] семантика: сегментатор ↔ OSM
   │                             ▼
   │                  INTEGRITY MONITOR
   │                  инлаеры ≥30 · covisibility ≥20% · острота пика
   │                  · χ²-гейт · согласованность N подряд
   │                             ▼
   └──────────► GTSAM iSAM2: одометрия + SE(2)-факторы
                              │
                    map_enu → odom коррекция + ковариация
                              │
                    MAVLink GPS_INPUT (eph/epv из Σ) ──► PX4 EKF2
```

## 6. Целевые показатели

| Метрика | Цель | Комментарий |
|---|---|---|
| Ошибка положения, p50 | < 10 м | Пол задаёт георефернция подложки (2–5 м CE90), не матчер |
| Ошибка положения, p95 | < 30 м | AnyVisLoc: 58.5% @20 м на спутнике; с накоплением фиксов реалистично |
| Курс после сходимости, p95 | < 0.5° | 0.5° на 10 км = 87 м бокового ухода |
| Валидных фиксов на первые 2 км | ≥ 5 | Условие сходимости курса |
| **Integrity failure rate** (принят, ошибка >50 м) | **< 0.5%** | Важнее точности |
| Макс. участок без фиксов | ≤ 3 км | При ATE FAST-LIVO2 ~1.4 м/км |
| Такт фиксов | 1–2 Гц | |
| Латентность фикса, p95 | ≤ 300 мс | |
| Такт FAST-LIVO2 | ≥ 10 Гц устойчиво | Не деградировать существующее |

**Доступность фиксов по типу местности** — планируемая, не гарантированная:

| Местность | Ожидание |
|---|---|
| Город / пригород | 60–90% |
| Дороги, инфраструктура | 40–70% |
| Пашня / поля | 20–50%, сильно сезонно |
| Лес | 5–20% (только семантика/рельеф) |
| Вода, снег, сплошная облачность | ~0 |

## 7. Что мы сознательно НЕ делаем

| Не делаем | Почему |
|---|---|
| Retrieval-сеть (VPR) в основном контуре | Приорное окно из ковариации решает ту же задачу на порядок дешевле |
| LoFTR / eLoFTR / XoFTR | На орто-геоданных **проваливаются**: TE >100 м, RE >97°, recall <23% (OrthoLoC Table 2) |
| Полный 6-DoF PnP на каждый кадр | Переопределён на near-planar сцене, неустойчив, вскрывает f–t_z ambiguity |
| `VISION_POSITION_ESTIMATE` в PX4 | Известный дрейф EKF2 (issue FAST-LIVO2 #126). Идём через `GPS_INPUT` |
| Собственный ортоплан (Tier 1) на первом этапе | Требует предполётного облёта. Держим как апгрейд точности на этап 3 |
| AirSim / Colosseum / Flightmare | Заархивированы либо не дают георефернцированного терраина и лидара |
| Blender-рендер как отдельный трек | Isaac Sim закрывает управляемый свип по солнцу и сезонам нативно |
