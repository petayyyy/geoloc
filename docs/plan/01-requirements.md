## 3. Геометрия съёмки

Камера: HFOV ≈ 90°, сенсор 1456 × 1088 (IMX296-класс, global shutter).
Ширина пятна на земле = 2 · H · tan(HFOV/2) = 2H при 90°.

| AGL | Пятно камеры | GSD снимка | Патч @ 0.5 м/px | Патч @ 0.3 м/px |
|---|---|---|---|---|
| 100 м | 200 × 150 м | 0.137 м | 400 × 300 px | 667 × 500 px |
| 125 м | 250 × 187 м | 0.172 м | 500 × 374 px | 833 × 623 px |
| 150 м | 300 × 225 м | 0.206 м | 600 × 450 px | 1000 × 750 px |

**Вывод:** GSD снимка в 1.5–3.5 раза лучше подложки. Запрос **всегда даунсемплим к GSD карты** — это не потеря, а выигрыш: даунсемплинг гасит мелкие детали, которых на спутнике физически нет, сокращая домейн-гэп.

**Рабочий GSD патча: 0.5 м/px.** Обоснование: OrthoLoC показывает стабильность до 512 px растра и рост TE на 44% при 256 px. При 0.5 м/px патч на 100 м AGL = 400×300 px — на границе; на 150 м = 600×450 px — комфортно. Ниже 100 м AGL система деградирует по этой причине, что и задаёт нижнюю границу профиля.

### Покрытие лидаром

Livox Avia: FOV 70.4° (H) × 77.2° (V).

| AGL | Пятно Avia (мгновенное) | Пятно камеры | Дефицит покрытия |
|---|---|---|---|
| 100 м | 141 × 160 м | 200 × 150 м | ~30% ширины кадра |
| 150 м | 212 × 240 м | 300 × 225 м | ~29% ширины кадра |

При накоплении за 1 с на 10 м/с полоса удлиняется на 10 м вдоль курса, но **по ширине дефицит остаётся**. Отсюда требование:

> **DR-01.** Локальный DSM формируется как композит: лидарное покрытие (высокая уверенность) + Copernicus DEM 30 м, ресемплированный (низкая уверенность). True-ortho несёт **карту уверенности по пикселям**; матчер взвешивает корреспонденции по ней, а covisibility считается только по зоне высокой уверенности.

## 4. Бюджет точности одиночного фикса

| Источник | Вклад (1σ) | Характер | Снижается? |
|---|---|---|---|
| Георефернция спутниковой подложки | **2–5 м** (местами 10+) | Систематический | Только GCP или онлайн-оценка bias |
| Ошибка attitude 0.2–0.5° @ 125 м AGL | 0.4–1.1 м | Случайный | Калибровка, качество IMU |
| Ошибка AGL (лидар даёт z напрямую) | 0.1–0.3 м | Случайный | Мал благодаря лидару |
| Остаточная ошибка DSM (лидарная зона) | 0.2–0.5 м | Случайный | — |
| Остаточная ошибка DSM (зона Copernicus 30 м) | 2–8 м | Систематический по участку | Взвешивание по уверенности |
| Ошибка временной синхронизации 10 мс @ 12 м/с | 0.12 м | Случайный | Аппаратный триггер |
| Матчер (0.5–2 px @ 0.5 м/px) | 0.25–1.0 м | Случайный | Файн-тюн, AdHoP |
| **Итого (лидарная зона)** | **~3–6 м** | | |
| **Итого (зона DEM)** | **~5–11 м** | | |

**Курс на один фикс.** При патче 500×375 px и точности матча 1 px, плечо ~250 px → σ_ψ ≈ atan(1/250) ≈ 0.23° в идеале. Реалистично с учётом неравномерности инлаеров: **0.5–1.5°**.

**Сходимость курса.** N независимых фиксов дают σ_ψ / √N. От 3° начальной: 5 фиксов → ~0.6–0.7°; 20 фиксов → ~0.3°; с фильтром и учётом корреляции по пройденному пути реально выходим на **<0.5° p95** к концу первых 2–3 км.

### 5.2 План бюджета фикса (такт 500 мс)

| Стадия | Ресурс | Целевое время |
|---|---|---|
| Накопление облака + deskew | 0.2 × A76 (фоново) | — |
| Растеризация локального DSM 0.5 м | Mali / A76 | 15 мс |
| Композит с Copernicus DEM + карта уверенности | A55 | 5 мс |
| Undistort + backward-projection true-ortho | **RGA / OpenCL** | 15 мс |
| XFeat* запрос (640×480 экв.) | **NPU core 0** | 20–35 мс |
| XFeat* окно карты (амортизированно) | **NPU core 1** | ~8 мс |
| Матчинг дескрипторов (int8, NEON или GPU) | A76 / Mali | 10–20 мс |
| MAGSAC SE(2), 1000 итераций | A76 | 5 мс |
| Integrity + ковариация | A55 | 2 мс |
| GTSAM iSAM2 инкремент | A76 | 5–15 мс |
| **Итого на фикс** | | **~85–120 мс** |

При такте 2 Гц это ~20% одного ядра A76 + периодическая загрузка NPU. Запас на резервный канал фазовой корреляции (~20 мс) есть.

> **Ключевые решения по оптимизации:** варп через RGA (аппаратный 2D-движок RK3588) или OpenCL на Mali — **не на CPU**; матчинг дескрипторов на NEON (int8 dot product) или на GPU; закрепление тредов за кластерами (`taskset`): FAST-LIVO2 на A76, geoloc-матчер на A76, IO/ROS на A55.

## 6. Требования к данным и калибровке

| ID | Требование |
|---|---|
| CAL-01 | Интринсики камеры: RMS репроекции ≤ 0.3 px, модель с учётом дисторсии |
| CAL-02 | Экстринсики камера ↔ лидар: ошибка ≤ 0.2° / 2 см. Валидация по проекции облака на изображение |
| CAL-03 | Экстринсики IMU ↔ лидар: из конфигурации Avia + уточнение онлайн в FAST-LIVO2 |
| CAL-04 | Временная синхронизация камера ↔ лидар ↔ IMU: ≤ 5 мс. Предпочтительно аппаратный триггер камеры → `CAMERA_TRIGGER` в Pixhawk |
| CAL-05 | Калибровка проводится заново после любой разборки/переустановки узла |
| DAT-01 | Подложка: минимум два провайдера на район, с указанием даты съёмки |
| DAT-02 | Georeference подложки проверяется по независимым GCP или RTK-траектории; bias документируется |

## 7. Интерфейсные требования к PX4

| ID | Требование |
|---|---|
| PX-01 | Глобальная поза подаётся через MAVLink `GPS_INPUT`, **не** через `VISION_POSITION_ESTIMATE` |
| PX-02 | Поля `eph` / `epv` заполняются из ковариации фикса (не константами) |
| PX-03 | `fix_type` понижается при деградации: 3 (3D fix) → 2 → 1 по мере роста ковариации |
| PX-04 | `satellites_visible` заполняется синтетически, монотонно связано с качеством фикса |
| PX-05 | `EKF2_AID_MASK` и `EKF2_HGT_MODE` настроены согласованно с источником высоты (лидар как range finder) |
| PX-06 | Failsafe: при потере фиксов >T секунд автопилот уведомляется, режим не меняется автоматически без подтверждения оператора |
| PX-07 | Задержка от кадра до `GPS_INPUT` компенсируется полем времени, а не игнорируется |
